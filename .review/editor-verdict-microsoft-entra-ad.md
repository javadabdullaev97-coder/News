# Editor verdict: microsoft-entra-ad

## Решение: publish

## Изменения в заголовке
**До**: Microsoft посоветовала бизнесу перенести управление доступом сотрудников в облако
**После**: без изменений (81 символ, укладывается в 60–90; субъект + глагол действия
попадают в первые 40 знаков; термин «Active Directory» в заголовок не вынесен —
использован общечеловеческий «управление доступом сотрудников», что соответствует
правилу раскрытия технических терминов для tech-рубрики).
Обоснование: заголовок уже соответствует редполитике, менять не за чем.

## Изменения в лиде
**До**: «Microsoft 13 августа опубликовала в корпоративном блоге рекомендации для бизнеса
— перейти от локального сервера Active Directory к облачному сервису управления доступом
Entra ID.» (23 слова — короче нормы 25–30)
**После**: «Microsoft 13 августа опубликовала в корпоративном блоге рекомендации для бизнеса
— перейти от локального сервера Active Directory к облачному сервису управления доступом
Entra ID, чтобы снизить зависимость от неё.» (28 слов)
Обоснование: добавил причину перехода — формулировку, которую сама Microsoft
использует в посте («снизить зависимость», см. цитату в теле). Новых фактов не внёс,
только раскрыл «зачем» до нормы длины лида. Опциональная правка №3 из списка
понижений fact-checker'а.

## Применённые понижения (список fact-checker'а, без повторной проверки)

1. **Абзац про подрядчиков/партнёров/ИИ-агентов** (понижение №2 из fact-check).
   Было: «К корпоративным системам также обращаются подрядчики, партнёры, поставщики
   и ИИ-агенты, которым нужны отдельные права доступа для работы с данными и сервисами»
   — фраза «нужны отдельные права доступа» была отнесена сразу ко всем четырём группам.
   Стало: два предложения — «...обращаются подрядчики, партнёры, поставщики
   и ИИ-агенты. По данным поста, отдельные права доступа для работы с данными
   и сервисами нужны прежде всего ИИ-приложениям и агентам.» Сузил утверждение
   до того, что реально сказано в источнике (там это сказано про AI applications
   and agents, не про весь список). Заодно разбил на два предложения — совмещённая
   версия из отчёта fact-checker'а была 27 слов, длиннее нормы в 25.

2. **Абзац про локальный сервер и Entra ID как «основную платформу»**
   (понижение №1 из fact-check). Было: «Локальный сервер может продолжать
   поддерживать отдельные устаревшие задачи, а Entra ID становится основной
   платформой для новых сценариев...» — оценка вендора о своём продукте без
   атрибуции. Стало: «По данным поста, локальный сервер может продолжать
   поддерживать отдельные устаревшие задачи. Entra ID при этом становится
   основной платформой для новых сценариев...» Добавил атрибуцию в начало
   и разбил на два предложения (объединённый вариант с добавкой «По данным
   поста» давал 26 слов — на 1 больше лимита).

3. **Лид** (понижение №3, опциональное) — применено, см. выше.

## Стилистические правки
- Кроме двух понижений и расширения лида, тело статьи не менял: атрибуция
  нейтральна («объяснил», «уточнила», «говорится»), канцелярита и AI-slop нет,
  расщеплённых сказуемых и цепочек родительного падежа нет, пассива нет,
  числа и даты оформлены по стандарту («13 августа», «31 июля 2026 года»,
  «Microsoft 365», без разделителей-ошибок).
- Проверил длину предложений после правок — все ≤25 слов (максимум 28 слов
  только в лиде, где это разрешённое отдельное правило: 25–30 слов).
- H2 «Пять признаков...» оставил — материал не про одно единственное событие,
  а про рекомендательный пост с пятью пунктами и отдельной цитатой о позиции
  Microsoft плюс блок про руководство Microsoft Learn: это расширенная новость,
  один H2 для неё разрешён и не выглядит искусственным дроблением.
- Концовки-заглушки («Что дальше» без даты) в тексте не было и не появилось —
  последний абзац просто фиксирует факт (документация Microsoft Learn обновлена
  31 июля), это допустимая концовка для новости.

## Что оставил как есть
- Оба источника (`techcommunity.microsoft.com`, `learn.microsoft.com`) — без
  изменений, оба проверены fact-checker'ом.
- Структура и порядок абзацев — без изменений, только точечные правки внутри
  двух абзацев по списку понижений.
- Тег «облачные технологии» из исходного списка убрал: такого тега нет
  в `config/generated/tag-vocabulary.json`, и он слишком общий рядом
  с уже специфичными «Active Directory» / «Microsoft Entra ID». Оставшихся
  четырёх тегов достаточно (мин. 3 по требованию).
