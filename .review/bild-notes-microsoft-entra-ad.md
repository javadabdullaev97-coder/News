## Почему не A (первоисточник)
Открыл оба `sources` через WebFetch:
- techcommunity.microsoft.com/.../why-active-directory-alone-is-no-longer-enough —
  статический HTML — SPA-обёртка без og:image в разметке (65 КБ, без `<img>`).
  Рендер через WebFetch нашёл одно изображение поста:
  https://techcommunity.microsoft.com/t5/s/gxcuf89792/images/bS00NTQ2NDAyLTFTTGN2Sg
  (850×567) — скачал и открыл: это стоковое фото женщины с Microsoft Surface
  (лого Windows на корпусе устройства), жанр «сотрудник за работой».
  Отклонено по прямому запрету handoff: «лица людей как иллюстрация
  «сотрудников»». Плюс разрешение 850px по короткой/850 по длинной стороне
  ниже 1600 — потребовался бы запрещённый апскейл (`scale > 1`).
- learn.microsoft.com/.../road-to-the-cloud-introduction — текстовая
  документация, WebFetch вернул только markdown-текст без единого
  изображения/диаграммы; схемы пяти стадий на странице нет.

Официального фото или содержательной инфографики по теме не нашлось —
переход к стоку.

### Выбранный вариант
- Источник: Unsplash, фотограф Albert Stoynov
- Прямая ссылка (оригинал 3000×2143):
  https://images.unsplash.com/photo-1744868562210-fffb7fa882d9
- Лицензия: Unsplash License (свободное коммерческое использование)
- Тип: живая фотография — патч-панель серверного шкафа с оптоволоконными
  коммутационными шнурами (жёлтые/зелёные), крупный план, без людей, без
  логотипов вендоров и конкурентов, без 3D-рендера и без «радуги» —
  двухцветная схема (жёлтый/зелёный), не разноцветный сток.
- Соответствие image-hint: закрывает часть «локальный сервер» из подсказки
  «локальный сервер против облака» — материал буквально про отказ от
  локальной серверной инфраструктуры (Active Directory) в пользу облака,
  кадр физического сетевого оборудования — нейтральная, но тематически
  точная иллюстрация именно той стороны, от которой Microsoft советует
  отказаться.
- Проверка на повтор: `node scripts/photo-dupes.mjs --check /tmp/cand5.jpg`
  → «свободен, за 2 дн. этот кадр не выходил».

## Обработка
```
python3 scripts/prepare-image.py /tmp/cand5.jpg microsoft-entra-ad --month=2026-08
```
```json
{
  "source": {"width": 3000, "height": 2143},
  "fit": {
    "mode": "cover",
    "scale": 0.5333,
    "cropLoss": 0.2126,
    "offset": [0, 60],
    "upscaled": false,
    "note": "обрезано 21% по высоте; окно кропа выбрано по содержимому"
  },
  "output": {
    "path": "public/images/posts/2026-08/microsoft-entra-ad-01.jpg",
    "url": "/images/posts/2026-08/microsoft-entra-ad-01.jpg",
    "width": 1600, "height": 900, "bytes": 240440, "quality": 90
  },
  "status": "ok",
  "upscaled": false
}
```
Cover-режим (не contain/подложка) — исходник горизонтальный. Обрезка 21,3%
(< 22% лимита скрипта и < 25% порога crop-risky из §3б). `crop-risky` не
применяю: это не фотография с явным физическим субъектом (человек/животное/
здание/документ), а абстрактный крупный план кабелей — случайная обрезка
краёв смысла не меняет, весь кадр остаётся читаемым.

## Уверенность в подборе: 68%
Живая фотография, горизонтальная, без людей, без логотипов конкурентов/
вендоров, без 3D-рендера и без радужной палитры — все ограничения из
handoff соблюдены. Снижение с эталонных 80–85%: материал без физического
субъекта (вендорский блог-анонс продукта), кадр иллюстрирует тему только
косвенно — «серверная инфраструктура» вообще, не конкретно Active
Directory/Entra ID и не сам продукт Microsoft. Более точного визуала
(интерфейс Entra ID, официальная схема пяти стадий перехода) в открытых
источниках не нашлось: пост в блоге отдаёт только фото сотрудника
(запрещено handoff), а страница Microsoft Learn — без иллюстраций вовсе.
