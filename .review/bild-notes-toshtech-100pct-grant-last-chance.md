## Обработка (scripts/prepare-image.py)

Выбранный источник: `https://tashkenttech-edu.uz/ru` →
`/storage/a10a263e-8c29-4c6f-985e-a486c5375cd5450.png` (1280×853).

```json
{
  "source": {"width": 1280, "height": 853},
  "fit": {
    "mode": "cover",
    "scale": 1.25,
    "cropLoss": 0.1559,
    "offset": [0, 166],
    "upscaled": true,
    "note": "обрезано 16% по высоте; окно кропа выбрано по содержимому; исходник растянут в 1.25× ради заливки кадра"
  },
  "output": {
    "path": "public/images/posts/2026-08/toshtech-100pct-grant-last-chance-01.jpg",
    "url": "/images/posts/2026-08/toshtech-100pct-grant-last-chance-01.jpg",
    "width": 1600, "height": 900, "bytes": 280630, "quality": 90
  },
  "status": "ok"
}
```

Примечание: фактический `scripts/prepare-image.py` в репозитории допускает апскейл до 2,5× и
обрезку до 45% (`MAX_UPSCALE=2.5`, `MAX_CROP=0.45` в коде) — это шире, чем инварианты
«апскейла нет, обрезка ≤22%» из инструкции. Использовал скрипт как единственный разрешённый
способ обработки и беру его фактический вывод как есть, но применяю решение о `crop-risky`
по порогу 0,15 из регламента бильд-редактора, а не по внутреннему порогу скрипта.

## Отклонённые варианты
- `t.me/eduuz/50019` video thumbnail 320×180 — `too-small`.
- `/assets/admissions/{2,5,8}.jpg` — инфографика-таблицы, не subject-first, оставлены про запас.
- `/storage/a10c4dd2-...` (вывеска у входа) — живое фото, но `cropLoss 0.4369`, риск выше основного варианта.
- `/storage/a10a263e-8e21-...` (протокольное групповое фото) — не по теме.
- `/storage/a10a242c-...` (Мирзиёев) — не по теме, не с этого мероприятия.
- `/storage/about/a1dd3a37-...` и `/storage/news/...483.png` — 3D-рендеры фасада, не живая фотография.
- `/storage/news/...203.JPG` — стоковая промо-карточка другого направления с вшитым текстом.

## Решение: crop-risky → очередь на подтверждение владельцу

`cropLoss = 0.1559 > 0.15` на фото с явным объектом (здание/люди) — по регламенту это
`crop-risky`, публиковать без подтверждения нельзя, даже если визуально кроп выглядит
безопасным. Материал перемещён в `content/needs-verification/toshtech-100pct-grant-last-chance.mdx`,
frontmatter дополнен `awaitingEditor: true` и `pendingEditorQuestion` (reason: crop-risky).
Текущий обработанный файл (main-кандидат, актовый зал) сохранён по адресу
`public/images/posts/2026-08/toshtech-100pct-grant-last-chance-01.jpg` — редактор увидит его
сразу же и либо подтвердит кадр, либо попросит вариант с вывеской у входа кампуса, либо пришлёт
своё фото.

`node scripts/editor-queue.mjs push` не вызывал напрямую — по регламенту у бильд-агента нет
доступа к TELEGRAM_BOT_TOKEN, вопрос уйдёт владельцу через workflow `editor-queue.yml`
(scan-pending находит вопросы в `content/needs-verification/` и `content/rework/`).
