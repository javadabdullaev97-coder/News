## Ход подбора

### A — первоисточники
- `huggingface.co/Qwen/Qwen3.8-2.4T-A95B` (карточка модели) — только аватар
  организации Qwen 200×200 (JPEG) → меньше `MIN_SOURCE=600`, `status: too-small`
  заведомо; и авто-сгенерированный HF social-thumbnail 1200×648
  (`cdn-thumbnails.huggingface.co/social-thumbnails/models/...`) — шаблонный
  разноцветный градиент huggingface.co с текстом `/Qwen3.8-2.4T-A95B`, не имеет
  отношения к бренду Alibaba/Qwen, читается как случайная HF-заглушка, а не как
  иллюстрация темы — отклонил.
- Официальный блог Qwen (`qwen.ai/blog?id=qwen3.8`, «Qwen3.8-Max: A New Bar for
  Coding and Cowork») — не открылся через WebFetch (JS-рендер, пустой контент),
  но открылся через `r.jina.ai`-ридер: первое изображение в посте — `performance.png`
  (бенчмарк-график), дальше только графики метрик и скриншоты кода/демо — по правилу
  «графики — почти никогда» не годится, обрезка в 16:9 режет подписи и легенду.
- Вордмарк `logo_qwen3.png` (3944×1555, landscape) из README `QwenLM/Qwen3` на
  GitHub — тот же файл уже отклонён в соседнем материале кластера
  (`bild-notes-alibaba-qwen-open-weights-laptop-ai.md`) как «плоский логотип на
  белом фоне, относится к Qwen3, не к Qwen3.8 конкретно». Перепроверил сам:
  прогнал через `prepare-image.py` — `cover`, `cropLoss 0.30` — автообрезка по
  содержимому съедает правый край и превращает надпись «Qwen3» в нечитаемое «Qwe»
  (окно кропа встало впритык к левому краю, где значок). При конвертации
  RGBA→RGB прозрачный фон также заливается чёрным вместо белого — визуально
  выглядит как брак. Источник отклонён окончательно.
- SCMP (`scmp.com/.../3363927/...`) — og:image явно подписан «Photo: Shutterstock
  Images» — чёрный список платных стоков, не берём даже как иллюстрацию к цитате.
- AI Business (`aibusiness.com/.../alibaba-qwen-3-8-27b...`) — og:image
  `eu-images.contentstack.com/.../Alibaba.jpg`, кредит «Getty Images» — тоже
  чёрный список, отклонил.
- `qwencloud.com`, `chat.qwen.ai` — иконки/логотипы отдают SPA-заглушку
  (`text/html` вместо картинки) при прямом запросе файла, не достать без
  рендеринга браузера.

## Обработка

```bash
curl -sL "https://images.unsplash.com/photo-1515879218367-8466d910aaa4?q=90&w=3000&auto=format&fit=max" -o /tmp/original.jpg
python3 scripts/prepare-image.py /tmp/original.jpg alibaba-qwen-license-large-companies --month=2026-08
```

```json
{
  "source": {"width": 3000, "height": 2003},
  "fit": {"mode": "cover", "scale": 0.5333, "cropLoss": 0.1575, "offset": [0, 86],
    "upscaled": false, "note": "обрезано 16% по высоте; окно кропа выбрано по содержимому"},
  "output": {"path": "public/images/posts/2026-08/alibaba-qwen-license-large-companies-01.jpg",
    "url": "/images/posts/2026-08/alibaba-qwen-license-large-companies-01.jpg",
    "width": 1600, "height": 900, "bytes": 272630, "quality": 90},
  "status": "ok", "upscaled": false
}
```

`cropLoss 0.1575` — ниже общего лимита 0.22 из редполитики и ниже порога
`crop-risky` (0.25); правило `crop-risky` в любом случае не применяется к этому
кадру — нет одного явного физического объекта (человек/животное/здание/
документ), это текстовая сцена, где потеря верхних строк кода не критична.
Проверил итоговый файл визуально: весь видимый код читается полностью, ни одна
строка не обрезана по горизонтали.

## Отклонённые варианты

- AI Business og:image — Getty Images, чёрный список.
