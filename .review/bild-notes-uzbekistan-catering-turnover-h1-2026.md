## Обработка (scripts/prepare-image.py)
```json
{
  "source": {"width": 800, "height": 533, "path": ".review/uzstat-original.jpg"},
  "fit": {
    "mode": "cover",
    "scale": 2.0,
    "cropLoss": 0.1557,
    "offset": [0, 35],
    "upscaled": true,
    "note": "обрезано 16% по высоте; окно кропа выбрано по содержимому; исходник растянут в 2.00× ради заливки кадра"
  },
  "output": {
    "path": "public/images/posts/2026-08/uzbekistan-catering-turnover-h1-2026-01.jpg",
    "url": "/images/posts/2026-08/uzbekistan-catering-turnover-h1-2026-01.jpg",
    "width": 1600,
    "height": 900,
    "bytes": 399637,
    "quality": 90
  },
  "status": "ok"
}
```
Режим `cover`, без подложки/полей — кадр залит целиком. Обрезка 15,6% по высоте, ниже порога
скрипта (MAX_CROP=0.45) и ниже порога `crop-risky` (0,25) для escalation. Апскейл 2.0×, в пределах
MAX_UPSCALE=2.5, зафиксированного в самом скрипте — так что растяжение штатное для этого пайплайна.

**Примечание о несостыковке документации**: `references/image-pipeline.md` описывает более старые
правила («апскейла нет никогда», «обрезка ≤22%»), которые не совпадают с текущим кодом
`scripts/prepare-image.py` (MAX_UPSCALE=2.5, MAX_CROP=0.45, разрешённый умеренный апскейл ради
cover-режима без подложки). Ориентировался на фактическое поведение скрипта — он источник истины
для рантайма, документация не актуализирована.

## crop-risky / eskalация
Не требуется — cropLoss 0,156 < 0,25, объект в кадре — общая сервировка стола (много предметов
по всему полю), а не единичное лицо/животное, которому обрезка могла бы срезать голову.

## Уверенность в подборе: 90%
Фото — прямое приложение к тому же посту Нацкомстата, что уже используется как основной источник
статьи, то есть атрибуция максимально чистая и релевантность теме прямая (общепит → узбекская
кухня на столе кафе/ресторана). Снимаю 10% за то, что снимок скорее иллюстративный/имиджевый
(не документальная съёмка конкретного заведения), но это в рамках допустимого для абстрактной
статистической темы без единичного субъекта.
