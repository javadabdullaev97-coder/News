Reporter (`rptr-notes-energy-passport-uzbekistan-mahalla-aug2026.md`): «Министр энергетики
Шерзод Ходжаев на трибуне/интервью, либо здание Минэнерго... Если фото министра нет —
подойдёт нейтральное изображение электро-/газораспределительной инфраструктуры (трансформаторная
подстанция, газовые трубы во дворе) как визуальная метафора энергопаспорта».
Задание отдельно указало: атрибуция интервью министру снята editor'ом как неподтверждённая —
картинку к конкретному человеку/министру привязывать нельзя. Поэтому вариант «фото Ходжаева»
исключён по редакционному решению, даже если бы нашёлся качественный кадр.

## Ход поиска

### A. Первоисточник (t.me/minenergy_uz)
- Проверил оба поста из `frontmatter.sources` (20692, 20679) и всю недавнюю ленту канала
  (20672–20692) через прямой `curl` HTML (не только через WebFetch — он в режиме `?embed=1`
  один раз подсунул аватар канала 160×160 вместо реального медиа поста, это известная ловушка
  из `image-pipeline.md`).
- Пост 20692 (сам первоисточник интервью) — og:image оказался кадром из видео 320×180:
  диктор на фоне студии с подписью «SHERZOD XO'JAYEV, ENERGETIKA VAZIRI». Отклонён **по двум
  независимым причинам**: (1) ниже `MIN_SOURCE=600` — `prepare-image.py` дал бы `too-small`;
  (2) даже будь он крупнее — это прямой портрет предполагаемого министра, а задание требует
  не привязывать картинку к конкретному человеку в этом материале.
- Пост 20679 (рабочая группа) — og:image 320×175, тоже видеокадр, тоже мал.
- Проверил соседние посты с групповыми альбомами (20687 — отчёт президенту, 20672 — конкуренция
  на рынке СУГ в Андижане): 800×533/800×600 фото людей за столами совещаний — не по теме
  энергопаспорта, есть узнаваемые официальные лица, не относящиеся к этому материалу
  (риск вводящей в заблуждение привязки). Один из кадров 20687 — портретный кадр человека
  у экрана с презентацией (похоже на министра) — отклонён по той же причине, что и 20692.
- Официальный сайт (minenergy.uz → редирект на gov.uz/ru/minenergy) — на странице
  и в её og:image только герб/логотип ведомства (`api-portal.gov.uz/.../*.png`) — не
  фотография, использовать как «главную картинку» нельзя (не живая съёмка).
- Итог: ни одного пригодного кадра инфраструктуры (подстанция, газовые трубы, ЛЭП) в
  первоисточнике за проверенный период не нашлось — канал публикует либо видеокадры людей,
  либо совещания, либо служебную графику.

## Обработка (`scripts/prepare-image.py`)
```json
{
  "source": {"width": 3000, "height": 2250},
  "fit": {
    "mode": "cover",
    "scale": 0.5333,
    "cropLoss": 0.25,
    "offset": [0, 300],
    "upscaled": false,
    "note": "обрезано 25% по высоте; окно кропа выбрано по содержимому"
  },
  "output": {
    "path": "public/images/posts/2026-08/energy-passport-uzbekistan-mahalla-aug2026-01.jpg",
    "url": "/images/posts/2026-08/energy-passport-uzbekistan-mahalla-aug2026-01.jpg",
    "width": 1600, "height": 900, "bytes": 196612, "quality": 90
  },
  "status": "ok"
}
```
`cropLoss = 0.25` — ровно на пороге `imagery.cropRiskThreshold` (0.25), не превышает его
строго (`>`), тот же случай, что в прецеденте `navoi-water-utility-decree-pf140`. Визуально
проверил итоговый кадр: обрезка целиком ушла в верхнюю часть неба, опора ЛЭП со всеми
проводами и силуэты домов на заднем плане остались в кадре полностью, ничего значимого не
срезано. Это горизонтальный пейзажный/инфраструктурный кадр без единого явного «объекта
с лицом» (не человек, не животное) — по правилу crop-risky порог применяется к фото с явным
объектом (человек/животное/здание крупным планом/документ); здесь ближайшая аналогия —
широкий пейзаж, где обрезка неба безобидна. Эскалацию `crop-risky` не открывал.
