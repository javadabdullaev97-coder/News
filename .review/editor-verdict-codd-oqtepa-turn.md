# Editor verdict: codd-oqtepa-turn

## Решение: publish

## Единственный источник (§7 «sources ≥ 2» — красный флаг, осознанное исключение)
Материал держится на одной записи в `frontmatter.sources` — официальном Telegram-канале
ЦОДД Ташкента (`config/telegram-channels.json`: type `source`, приоритет P1 — это канал
самого ведомства, а не третьей стороны). Reporter задокументировал в notes, что второй
независимый источник не найден: сайта `codd.uz` в открытом поиске нет, другие профильные
каналы новость не ретранслировали. Fact-checker подтвердил (`approve`, confidence 90) и
явно передал решение о маршруте на моё усмотрение.

Решение: **публикую напрямую, без editorReview/вопроса владельцу.** Основания:
1. Тема рутинная и не чувствительная по разделу 8 (не уголовное дело, не ЧП, без
   персональных данных и обвинений) — просто изменение организации движения на одном
   перекрёстке.
2. Единственный источник — официальный канал первого приоритета (P1), сообщающий
   о собственном решении, а не третья сторона о чужом ведомстве. Риск недостоверности
   минимален.
3. Есть прямой прецедент в архиве редакции для того же профиля новостей: в
   `.review/fact-check-codd-akkurgan-parkent-closure.md` editor уже принимал единственный
   источник ЦОДД как «не блокирует публикацию (рутинное оперативное объявление профильного
   органа, а не чувствительная тема по §8)» — тот же логический случай.
4. Аналогичные прецеденты для других ведомств (`editor-verdict-khorezm-investment-problems-prosecutor-review.md`,
   `editor-verdict-fergana-rowing-base-construction-aug2026.md`, `fact-check-yunusabad-smart-gas-points-modernization.md`)
   показывают устойчивую практику редакции: единственный официальный P0/P1-источник
   по нерезонансной теме — принятое исключение из §7, а не повод для ручного review.

Исключение зафиксировано явно, `sources` не менял.

## Дата события не подтверждена — не проставляю publishedAt
Reporter и fact-checker оба отметили: точное время публикации поста ЦОДД (`/302`)
инструментами не извлекается (WebFetch отдаёт только упрощённый рендер без datetime).
Драфт пришёл с `publishedAt`, фактически равным дню обработки темы (21 августа) — это
не подтверждённая дата события, а дата написания материала, выдавать её за настоящую
нельзя.

**Действие**: заменил `publishedAt` на `queuedAt` (тот же таймстемп, честно помечен как
момент постановки в очередь). Настоящий `publishedAt` проставит `scripts/publish-tick.mjs`
в момент реального выхода — это стандартный путь для материалов без подтверждённого
времени события, тот же приём применён в `editor-verdict-mygovuz-language-proficiency-test-aug12.md`.

**Лид без даты события.** По той же причине не могу вставить в лид дату/временной маркер
(«31 июля», «на этой неделе») — у меня нет подтверждённого основания даже для
приблизительной формулировки, а придумывать её — то же самое нарушение точности, которое
правило про дату в лиде должно предотвращать. Это осознанное отступление от правила
«лид обязателен с датой события» (раздел «Лид» редполитики), задокументированное здесь,
а не тихая недоработка. Reporter прямо предложил такой выход («согласовать с editor
формулировку без даты в лиде»).

## Изменения в лиде
**До**: «Центр организации дорожного движения (ЦОДД) Ташкента сообщил, что на перекрёстке
площади Октепа изменилась схема левого поворота — водители получили возможность
поворачивать налево напрямую по сигналу светофора, без объезда через улицу Муқимий.»
(30 слов)
**После**: «Центр организации дорожного движения (ЦОДД) Ташкента сообщил, что на
перекрёстке площади Октепа изменилась схема левого поворота: водители теперь
поворачивают налево напрямую по сигналу светофора, без объезда через улицу Муқимий.»
(29 слов)
Обоснование: убрал канцелярскую конструкцию «получили возможность» → прямое «теперь
поворачивают» (активнее, короче); заменил тире на двоеточие — вторая часть раскрывает
первую, а не противопоставляет. Длина лида в норме 25–30 слов. Дату сознательно не
добавил — см. раздел выше про неподтверждённую дату события.

## Стилистические правки
- Разбил длинное предложение об старой схеме (28 слов, с расщеплённым «были обязаны
  сначала выехать») на два коротких: описание манёвра (20 слов) + отдельное
  предложение-атрибуция «Об этом сообщил ЦОДД» (4 слова, ссылка сохранена на том же URL).
- Заменил «были обязаны сначала выехать» → «должны были заехать» — короче, без потери
  смысла.
- Заменил пассивную атрибуцию «говорится в публикации на канале ЦОДД» → «сообщил ЦОДД»:
  это официальный канал самого ведомства, сообщающего о собственном решении (не личный
  канал руководителя, где действует запрет на «написал»), прямая атрибуция корректна
  и короче.
- «Тот же манёвр совершается» (пассив) → «водители выполняют этот манёвр» (актив).
- «В ведомстве уточнили» → «ЦОДД уточнил» — прямой субъект вместо безличной конструкции.
- Разбил последнее предложение (22 слова: «...ввели, чтобы упростить..., сократить...
  и предотвратить...») на два: причина введения (17 слов) + отдельным предложением цель
  «Это должно предотвратить заторы на перекрёстке» (6 слов). Медиана длины предложений
  тела текста снизилась до нормы (было 22/18/22 слов, стало 20/4/16/17/6 — медиана 16).
- Убрал тройное перечисление целей одним рядом (упростить/сократить/предотвратить) —
  разбил на «упростить и сократить» + отдельно «предотвратить», меньше нагрузки на
  предложение.

Ни один из трёх жёстких триггеров не сработал:
1. Слов убрано: было 98 (лид + два абзаца тела), стало 92 — сокращение ≈6%, далеко
   от порога 15%.
2. Абзац со ссылкой на источник не снимался целиком — ссылка сохранена, только
   переставлена внутри того же абзаца на короткое атрибутирующее предложение.
3. Новых inline-ссылок и новых записей в `frontmatter.sources` не добавлял.

## Что оставил как есть
- Единственный источник в `sources` — решение задокументировано выше, не мой источник
  для проверки, повторно не перепроверяю.
- Структура: новость об одном событии, H2 нет, концовка — контекст последней фразой
  («это должно предотвратить заторы»), без блока «Что дальше» — по объявленному шагу
  или дате материал не располагает, блок был бы имитацией.
- Объём текста (~92 слова) короче ориентира 150–350 слов для новости об одном событии —
  не растягиваю искусственно: исходный материал держится на одном коротком посте, добавлять
  факты, которых там нет, запрещено.
- `image.url/alt/credit` — `null`, передаю дальше `bild`.
