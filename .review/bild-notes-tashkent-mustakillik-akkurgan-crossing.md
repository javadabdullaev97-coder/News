## Обработка кандидата (для протокола, `prepare-image.py`)

```json
{
  "source": { "width": 800, "height": 577 },
  "fit": {
    "mode": "cover",
    "scale": 2.0,
    "cropLoss": 0.2201,
    "offset": [0, 0],
    "upscaled": true,
    "note": "обрезано 22% по высоте; окно кропа выбрано по содержимому; исходник растянут в 2.00× ради заливки кадра"
  },
  "output": { "width": 1600, "height": 900, "bytes": 258255, "quality": 90 },
  "status": "ok"
}
```

Скрипт (актуальная версия, `MAX_UPSCALE=2.5`, `MAX_CROP=0.45`) пропустил кадр в `cover`:
апскейл 2.0× ≤ 2.5×, `cropLoss` 0.22 ≤ 0.45 — формально это «ок». Обрезка (сверху сохранён
весь кадр, снизу срезано 22% высоты) не портит контент: заголовок, легенда, названия улиц
(Мустақиллик, Оққўрғон, Осиё, КҲАЙ) остаются полностью читаемы — самодостаточный кусок по
правилу про графики/инфографику.

## Почему кандидат всё равно не пошёл прямо в статью

1. **Это схема, не живая фотография.** Handoff прямо просил «дорожный знак или разметку
   поворота, общий план проспекта» — то есть съёмку, а не карту. Официальная инфографика
   с реальными данными формально допустима политикой («не заготовка»), но это крайний случай,
   не первый выбор, когда есть более удачная альтернатива... которой, впрочем, не нашлось.
2. **Главная причина — конфликт с editorial handoff.** На карте крупно читается подпись станции
   метро «Пушкинская / Pushkin» прямо у отмеченного места перекрытия (нижняя правая четверть
   кадра). `image-avoid` в handoff прямо требует не привязывать материал к «скверу Пушкина» —
   эту деталь редактор снял из текста как неподтверждённую. Ставить картинку, где «Пушкин»
   читается крупным планом, было бы визуальным возвратом вычеркнутой детали — решил не брать
   на своё усмотрение, вопрос ушёл владельцу.
