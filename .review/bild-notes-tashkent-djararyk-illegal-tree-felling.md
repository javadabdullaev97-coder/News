# Bild notes: tashkent-djararyk-illegal-tree-felling

## Стратегия: primary-source

## Источник картинки
- Пост: https://t.me/Ecopoytaxt/36001 (официальный Telegram-канал Главного
  управления экологии и изменения климата города Ташкента).
- WebFetch/`curl` на прямой URL поста отдаёт JS-обёртку без медиа (та же проблема,
  что у reporter'а), но `?embed=1` виджет вернул полный HTML с альбомом из 6
  вложений группы + отдельный `og:image`. Скачал все 6 напрямую с CDN
  (`cdn4.telesco.pe/...`) и просмотрел:
  - `og:image` (320×320) — декоративная зелёная карточка «RASMIY MUNOSABAT!»,
    не фото — не годится.
  - 36003 (800×717) — жилая многоэтажка, без явной привязки к участку —
    отклонено, есть кадр точнее.
  - 36004 (800×688) — инспекторы и местная жительница за столом на месте —
    отклонено: в кадре узнаваемые лица, а статья намеренно не идентифицирует
    нарушителя («местный житель» без деталей) — публикация фото противоречила бы
    этому решению reporter/editor.
  - 36005 (800×600) — **выбрано.** Реальное фото самого участка на Джарарыке:
    голая земля со строительным мусором, один сохранившийся ствол дерева,
    открытый колодец, жилая застройка на фоне. Без людей, горизонтальная
    ориентация (соотношение 1,33). Прямое визуальное подтверждение состояния
    участка, о котором пишет статья.
  - 36006, 36007 — скриншоты интерфейса карты green.tashkent.uz (зелёные точки
    деревьев, всплывающая подсказка «112»). Отклонено по правилу «графики и
    скриншоты — почти никогда»: мелкий UI-текст нечитаем в кадре 16:9, обрезка
    неизбежно теряет часть интерфейса.

## Обработка (scripts/prepare-image.py)
```json
{
  "source": {"width": 800, "height": 600},
  "fit": {
    "mode": "cover",
    "scale": 2.0,
    "cropLoss": 0.25,
    "offset": [0, 135],
    "upscaled": true,
    "note": "обрезано 25% по высоте; окно кропа выбрано по содержимому; исходник растянут в 2.00× ради заливки кадра"
  },
  "output": {
    "path": "public/images/posts/2026-08/tashkent-djararyk-illegal-tree-felling-01.jpg",
    "url": "/images/posts/2026-08/tashkent-djararyk-illegal-tree-felling-01.jpg",
    "width": 1600, "height": 900, "bytes": 385287, "quality": 86
  },
  "status": "ok"
}
```
Источник ограничен 800px по длинной стороне — это технический потолок
публичного Telegram-виджета (см. `image-pipeline.md`), апскейл 2× и cover-режим
в этом случае ожидаемы, не признак неправильного выбора кадра. cropLoss = 0,25
— ровно на границе, не выше порога crop-risky (>0,25) из инструкции; на итоговом
кадре не потеряно ничего значимого (срезаны верхняя полоса неба и нижняя полоса
переднего плана с мусором, сам сюжет — участок, дерево, колодец — виден целиком,
проверено визуально).

## Отклонённые варианты
- og:image (декоративная карточка) — не фотография.
- 36003 (жилой дом) — слабее по конкретике, чем 36005.
- 36004 (инспекторы + местная жительница) — узнаваемые лица, риск для
  анонимности нарушителя, которую сознательно сохранили reporter/editor.
- 36006, 36007 (скриншоты карты реестра) — UI-скриншот, запрещён политикой
  «графики/скриншоты — почти никогда».

## Уверенность в подборе: 82%
Фото — подлинный кадр непосредственно с места проверки, опубликованный самим
ведомством в том же посте, который служит основным источником статьи; показывает
именно тот участок, о котором идёт речь. Минус к уверенности — сама фотография
не показывает свежие пни (в посте таких кадров нет вовсе, только этот общий вид
участка и кадр с инспекторами), поэтому это ближе к «запасному варианту» из
mainVisualSubject reporter'а, а не к идеальному «пни вырубки». Также источник
ограничен разрешением 800×600, потребовался 2-кратный апскейл в рамках лимитов
скрипта.
