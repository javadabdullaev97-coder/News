# Fact-check: azure-breach-claim-2026-08

## Общий вердикт: APPROVE-WITH-DOWNGRADES

Материал в целом добросовестно держит атрибуцию неподтверждённого заявления хакера, но есть точечные места, где формулировка соскальзывает с «хакер утверждает» на констатацию факта, плюс потеря точности у части цифр. Все лечится понижением формулировок без повторной проверки.

## Проверенные утверждения (ключевые)

- Заявление хакера (псевдоним TheHatman) о краже 3,6 млн записей из тенанта Azure через password spray + MFA fatigue, продажа с 31 июля — ✅ CONFIRMED, дата 31 июля перепроверена вручную напрямую в источнике.
- Цифры по McDonald's (1,7+ млн), TCS (800+ тыс.), Vodafone (425+ тыс.) — ✅ CONFIRMED, знак приблизительности сохранён корректно.
- Цифры по HCL (250k), IHG (185k), Kyndryl (170k), Gap (80k), Hexaware (20k), Wyndham (9k) — ⚠️ PARTIAL: источник даёт их со знаком «+» для всех восьми компаний, но в тексте знак сохранён только для первых двух — 6 из 8 поданы как точные числа.
- Ответы TCS («нет доказательств взлома, данные могут быть 4-летней давности») и Gap («данные ограничены, не чувствительны, старые») — ✅ CONFIRMED дословно.
- «Microsoft заявление хакера не прокомментировала» — ❌ UNSUPPORTED в текущей формулировке: ни BleepingComputer, ни SecurityWeek вообще не упоминают Microsoft — ни как запрошенную, ни как отказавшуюся комментировать сторону. Фраза шире того, что источники устанавливают.
- Второй независимый источник SecurityWeek (другой автор, та же дата) — ✅ CONFIRMED, независимость подтверждена.

## Дополнительная находка атрибуции

В блоке «Какие компании упомянуты»: «Остальные компании потеряли меньше» — глагол «потеряли» констатирует утечку как факт, рассинхрон с остальным текстом, где атрибуция выдержана железно.

## Оценка целесообразности взятия темы

Источник citable:true (BleepingComputer P2), заголовок/лид формулируют событие как заявление («заявил», не «взломали»), не повтор без новой стадии. Дополнительно применяется tier1Floor — Microsoft это гарантирует. Взятие темы оправдано редполитикой.
