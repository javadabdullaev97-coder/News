## Правило, ради которого всё это разнесено

**Случился инцидент — в инструкцию идёт ОДНА строка правила, разбор идёт
сюда.**

Агенту не нужно знать, почему правило такое: ему нужно знать, что делать.
Абзац «а вот 09.08 случилось вот что» оплачивается токенами на каждой статье
и на каждом прогоне — то есть сотни раз, — а прочитан по делу ноль раз.
Человеку, который правит правило через месяц, разбор нужен обязательно:
без него правило выглядит произвольным и однажды будет «упрощено» обратно.

Что остаётся в инструкции:
- само правило, в повелительном виде;
- пример «плохо / хорошо», если правило без примера непонятно;
- имя скрипта, который правило проверяет.

Что уходит сюда:
- даты и номера инцидентов, «раньше было / стало»;
- проценты замеров и сравнения с конкурентами;
- объяснения, почему выбрали этот вариант, а не соседний.

## Что сторожит границу

- `node scripts/prompt-budget.mjs` — потолок размера для каждого файла,
  который агенты читают на каждом материале. Ежедневно в `policy-drift.yml`.
  Рост разрешён, но отдельным коммитом: `--update`.
- `node scripts/rules-inventory.mjs` — снимок всех нормативных пунктов
  инструкций. Перед крупной переписью: `--save`, после — сверка. Показывает
  поимённо, какое правило исчезло.
- `node scripts/policy-slice.mjs --coverage` — каждая ли часть редполитики
  доставлена хотя бы одной роли. Правило, которого никто не читает,
  не действует.
