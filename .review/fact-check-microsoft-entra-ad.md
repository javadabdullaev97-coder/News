## Проверка specialRules.vendorSpeaksAboutItself (tech-рубрика)

Правило соблюдено в основном: оценочная цитата Microsoft («цель не обязательно заменить... а снизить зависимость») подана как прямая атрибутированная цитата в кавычках — образцово. Один пункт слабее:

- Предложение «Локальный сервер может продолжать поддерживать отдельные устаревшие задачи, а Entra ID становится основной платформой для новых сценариев» идёт сразу после цитаты, но само по себе не промаркировано как пересказ позиции Microsoft — читатель, вырвавший предложение из контекста, прочитает это как утверждение редакции. Источник называет Entra ID «preferred platform» — это оценка вендора о своём же продукте.

## Список понижений для editor'а (применяет сам, без повторной проверки)

1. Абзац 4 (после квоты): «Локальный сервер может продолжать поддерживать отдельные устаревшие задачи, а Entra ID становится основной платформой для новых сценариев...» → добавить атрибуцию в начало: «По данным поста, локальный сервер может продолжать поддерживать отдельные устаревшие задачи, а Entra ID становится основной платформой для новых сценариев...» — чтобы оценка вендора о собственном продукте не читалась как факт от редакции.
2. Абзац 3: «К корпоративным системам также обращаются подрядчики, партнёры, поставщики и ИИ-агенты, которым нужны отдельные права доступа для работы с данными и сервисами» → сузить последнюю часть до источника: «...партнёры, поставщики и ИИ-агенты — а ИИ-приложениям и агентам, по данным поста, нужны отдельные права доступа для работы с данными и сервисами», чтобы не приписывать требование «отдельных прав доступа» подрядчикам и партнёрам, о чём источник прямо не говорит.
3. (Опционально, не факт-чекерское, а редакционное) Лид короче нормы (~23 слова против 25–30) — editor может слегка расширить для соответствия чек-листу, например добавив уточнение про облачный Entra ID во второй части предложения.
