### Почему карточка отклонена

Это не съёмка события, а многоразовая заготовка канала — один и тот же файл стоит на разных
анонсах отключений, без дат и адресов. Содержание: водопроводный кран крупным планом с каплей,
за ним размытый рабочий в оранжевом жилете, экскаватор, конусы, каска и разводной ключ на земле,
поверх — вектор­ная жёлто-красная вывеска «SUV O'CHIRILDI / TA'MIRLASH ISHLARI».

При увеличении (кроп 400×533 → 800×1066) видно, что база не фотографическая:
кран висит на трубе, которая никуда не ведёт и ничем не закреплена; у рабочего не читаются руки
и инструмент, геометрия жилета «плывёт»; стрела экскаватора анатомически невозможна; ключ
сливается с полем каски; грунт смазан без структуры. Это сгенерированный/собранный сток-коллаж
с наклеенной графикой, то есть ровно та «заготовка», которую запрещает
`config/newsroom-policy.json → imagery.rejectStockRenders` и раздел «Чего мы хотим от картинки».

Отдельно: карточка не проходит и по атрибуции. Поставить под ней `credit: "Пресс-служба
Toshkent shahar suv ta'minoti"` — значит выдать читателю рендер за фотографию ведомства
с места работ. Прозрачность атрибуции важнее эстетики, поэтому вариант снят, а не «прикреплён
с оговоркой».

## Обработка (прогон карточки через `prepare-image.py`, для протокола)

Скрипт отработал штатно — то есть отклонение сделано по содержанию кадра, а не по кропу:

```json
{
  "source": { "width": 800, "height": 533 },
  "fit": {
    "mode": "contain",
    "scale": 1.0,
    "placed": [800, 533],
    "note": "вписано целиком на размытую подложку из самого кадра; заливка кадра потребовала бы растянуть исходник в 2.00×"
  },
  "output": { "width": 1600, "height": 900, "bytes": 143134, "quality": 90 },
  "status": "ok",
  "upscaled": false
}
```

`cropLoss` не возникает вовсе (режим `contain`), порог 0,15 не при чём — причина очереди
`stock-render`, а не `crop-risky`. Публичный виджет Telegram отдал ожидаемые 800px по длинной
стороне, апскейла скрипт не делал.

Результат прогона **убран из `public/`**, чтобы неодобренный кадр не лежал в публичной папке:
- `.review/bild-candidate-original-tashkent-water-shutoff-aug-3.jpg` — оригинал карточки 800×533;
- `.review/bild-candidate-tashkent-water-shutoff-aug-3.jpg` — та же карточка после
  `prepare-image.py`, 1600×900, 143 КБ (как выглядела бы в статье).

## Очередь редактору

Команда (проверена в `DRY_RUN=1`, текст сообщения владельцу собирается корректно):

```bash
node scripts/editor-queue.mjs push \
  --slug=tashkent-water-shutoff-aug-3 \
  --title="Воду в 22 махаллях Ташкента отключат на сутки с 10:00 3 августа" \
  --reason=stock-render \
  --question="У оператора на оба поста стоит одна и та же дежурная карточка: сгенерированный сток-коллаж (кран в воздухе, размытый рабочий, экскаватор) с наклеенной вывеской «SUV O'CHIRILDI». Живой съёмки работ, задвижек или подвоза воды в постах 5395/5396/5397 нет, в канале за неделю — только совещания и инфографика. Публиковать такое под кредитом пресс-службы = выдавать рендер за фото. Ставим эту карточку, пришлёте своё фото или выпускаем без картинки?" \
  --image=.review/bild-candidate-original-tashkent-water-shutoff-aug-3.jpg
```

**Внимание редактору поручений.** В этом прогоне `push` завершился с кодом 1:
`Нужны TELEGRAM_BOT_TOKEN и TELEGRAM_EDITOR_CHAT_ID`. Переменных в окружении нет,
`content/state/editor-queue.json` не создан — записи в `pending` **нет**, сообщение владельцу
не ушло. Команду выше нужно выполнить в среде с секретами (workflow `editor-queue.yml`).
Блокировку это не ослабляет: `awaitingEditor: true` уже стоит в файле, и материал не выйдет
независимо от состояния очереди. Но без реального `push` владелец вопроса не увидит,
и напоминания через 2 ч / сутки не заработают.

Оговорка про ответ «ок»: `applyAnswer` в этом случае просто снимает `awaitingEditor`,
`image.url` остаётся `null`, и статья выйдет без картинки (`build-posts.mjs` оставит
предупреждение «не заполнен image.url», сборку это не роняет). То есть «ок» = осознанный
выпуск без картинки, а не автоподстановка карточки оператора.
