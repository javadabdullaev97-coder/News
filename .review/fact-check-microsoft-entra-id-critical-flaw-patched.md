# Fact-check: microsoft-entra-id-critical-flaw-patched

## Общий вердикт: APPROVE-WITH-DOWNGRADES

## Решение по недоступному MSRC

Fact-checker самостоятельно пробовал открыть msrc.microsoft.com/update-guide/vulnerability/CVE-2026-69836 — тот же результат, что у репортёра: SPA отдаёт только заголовок страницы. Вместо повторных попыток факт проверен через альтернативный официальный источник — NVD (nvd.nist.gov, правительственный реестр уязвимостей США):

- CVE-2026-69836 — существует ✅
- CVSS 3.1: 10.0 CRITICAL, вектор AV:N/AC:L/PR:N/UI:N/S:C/C:H/I:H/A:H ✅ (вектор подтверждает «без пароля и без участия пользователя» независимо от пересказа Hacker News)
- Affected Component: Microsoft Entra ID ✅
- Механизм: деsериализация непроверенных данных, CWE-502 ✅
- Publication: 20 августа 2026 у NVD (в драфте — 21 августа/четверг, возможен разброс часовых поясов)
- Активная эксплуатация «в атаках» — NVD не фиксирует такой статус; CISA KEV не открылся (403)

Вывод: не применяется тяжёлый сценарий "первоисточник назван, но недоступен" (приложение 10.1) — ядро факта (CVE/CVSS/механизм/компонент) уже независимо подтверждено официальным реестром NVD, а не только пересказом одного СМИ. Единственное неподтверждённое независимо звено — статус активной эксплуатации — понижается до явной атрибуции, а не снимается и не требует reject.

## Проверенные утверждения (кратко)

Подтверждено независимо через NVD: CVE-номер, CVSS 10.0, механизм (десериализация), поражённый компонент (Entra ID), характер атаки без пароля/участия пользователя (по вектору PR:N/UI:N).
Подтверждено только вторичной прессой (thehackernews + по словам репортёра — cybersecuritynews.com, cyberpress.org): факт активной эксплуатации в атаках, дата бюллетеня, автоматическая установка патча.
Дата публикации — расхождение на день с NVD (20 vs 21 августа), не критично, вероятно часовые пояса.
