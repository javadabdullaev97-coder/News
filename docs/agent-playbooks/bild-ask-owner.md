# Бильд: когда кадр подтверждает человек

Открывается в четырёх случаях: картинки нет нигде (`no-image`), обрезка
рискованная (`crop-risky` — `cropLoss` больше 0,25 на фотографии с явным
объектом), нашлась только рисованная 3D-заготовка (`stock-render`), есть
сомнение в правах или в соответствии тексту (`source-doubt`).

Есть случаи, где эвристика заведомо проигрывает. В них материал не публикуется
вслепую, а уходит владельцу на подтверждение.

| `reason` | Когда |
|---|---|
| `no-image` | Картинки нет нигде: ни в первоисточнике, ни в стоке |
| `crop-risky` | `prepare-image.py` вернул `cropLoss` больше **0,25** |
| `stock-render` | Нашлась только рисованная 3D-заготовка, живой фотографии нет |
| `source-doubt` | Сомнение в правах на картинку или в её соответствии тексту |

**`crop-risky` — только для фотографий с явным объектом** (животное, человек,
здание, документ): умный кроп по центру масс лучше центрального, но гарантии
не даёт. На инфографике и схемах порог не применяется — обрезка полей там
безобидна.

**`editor-queue.mjs push` не вызывай.** Секреты Telegram живут только внутри
GitHub Actions, у тебя их нет — команда упадёт на `Missing TELEGRAM_BOT_TOKEN`.
Вопрос владельцу отправляет workflow,
твоя часть — подготовить материал:

1. **Перемести файл** из `content/drafts/<день>/<slug>.mdx` в
   `content/needs-verification/<slug>.mdx`. Критично: `scan-pending` ищет
   вопросы там (и в `content/rework/`), а не в `content/drafts/`. Оставишь
   в drafts — материал зависнет с `awaitingEditor: true` навсегда, вопрос
   не уйдёт.

2. **Обнови frontmatter**:
   ```yaml
   awaitingEditor: true
   pendingEditorQuestion:
     reason: "crop-risky"    # или no-image / stock-render / source-doubt
     question: "cropLoss 0.25+, лицо в кадре может обрезаться. Подтвердить кадр или прислать другой?"
     image: "public/images/posts/2026-08/<slug>-01.jpg"   # опционально
   ```

3. Верни `STATUS: fallback-needed` и укажи в notes, что материал в очереди.

Дальше `editor-queue.yml` найдёт материал через `scan-pending`, отправит вопрос
владельцу и добавит запись в очередь; после ответа `promoteToPosts()` вернёт
материал в `content/posts/<день>/`. Планёрка не ждёт — продолжает с остальными
темами. Напоминания владельцу: первые три раз в два часа, дальше раз в сутки.
**Молчание никогда не означает «публикуй как есть».**

Присланное владельцем фото окажется в `.review/editor-photo-<slug>.jpg` —
`prepare-image.py` внутри `editor-queue.mjs` прогонит его как обычный исходник
и вставит в статью.
