## Условный шаг: разгрести needs-verification

Открывается, когда `preflight.cards.matured` не пуст. Делается до отбора
новых тем, сразу после rework.

**Делается до отбора новых тем, сразу после rework.**

В `content/needs-verification/` два типа файлов, путать нельзя:

1. **Готовые материалы (`.mdx`)** с `awaitingEditor: true` — ждут владельца.
   Ими занимается `editor-queue.mjs`, не трогай.
2. **Исследовательские карточки (`.md`)** — не выпущены, потому что нет
   первоисточника. Владельцу показывать бессмысленно — нужно сходить
   и посмотреть, не появился ли источник. **Это твоя работа, и ничья больше.**

Ограничение `scanPending()` на `.mdx` — не баг, а именно эта граница. Не «чини».

### Что делать

1. Прочти все `.md` в `content/needs-verification/`. Срок — из `recheckAt`
   (frontmatter) или строки «Перепроверить» / «Проверить снова».
2. Отбери созревшие. Карточка без внятного срока созревает через 24 часа
   после заведения.
3. По каждой созревшей запусти `reporter` с обычным входом плюс:
   **бюджетом**: перепроверка — это не новое исследование, а один вопрос
   «появился ли первоисточник». Потолок — **шесть походов в сеть**, и только
   по адресам из раздела «Что проверить в первую очередь». Ни обхода
   конкурентов, ни поиска смежных тем, ни повторной сверки того, что карточка
   уже зафиксировала как устойчивое (сверенный документ, опубликованная
   стратегия, старый релиз): это уже проверено и не меняется.
   ```
   RECHECK_INPUT: {
     card_path: content/needs-verification/<slug>.md,
     blockers: "<из раздела «Почему не опубликовано»>",
     what_to_check: "<из раздела «Что проверить в первую очередь»>"
   }
   ```
   Reporter'ы по разным карточкам независимы — запускай параллельно.
4. По результату:
   - **первоисточник появился** → обычный цикл `fact-checker → editor →
     bild`, карточка удаляется;
   - **всё ещё нет** → допиши, что проверено, и назначь срок **скриптом,
     а не руками**:

     ```bash
     node scripts/recheck-schedule.mjs <карточка> --nothing
     # корреспондент назвал дату, раньше которой источника быть не может:
     node scripts/recheck-schedule.mjs <карточка> --nothing --not-before=2026-11-01
     ```

     Скрипт ведёт лестницу: 4 часа → сутки → 3 дня → неделя → две → месяц.
     Седьмой пустой круг помечает карточку `exhausted: true` — такую закрывай
     в `content/rejected/` с причиной «первоисточник так и не появился».
     Ставить срок на глаз нельзя: 20.08.2026 карточка сама написала, что
     документ внесут не раньше конца года, и назначила себе перепроверку
     на завтра — сто повторов проверки на 45 тысяч токенов с заранее
     известным ответом;
   - **тема протухла** (событию больше недели, поворотов нет) → в
     `content/rejected/` с причиной.
5. В отчёт: сколько созрело, разморожено, ждёт, списано.

**Новые карточки заводи с машиночитаемым сроком**: `recheckAt` в ISO-8601 во
frontmatter обязателен. Прозаическое «через 4 часа» можно оставить для
человека, но опираться на него нельзя.

**Потолок**: созрело больше пяти — возьми пять самых свежих по дате заведения,
остальным перенеси срок на следующий прогон и напиши об этом в отчёте.

Что созрело и сколько кругов уже прошло — `node scripts/recheck-schedule.mjs --due`.
Помни цену: одна перепроверка стоит как новая статья (40–60k токенов,
2–4 минуты). Карточка, которая шесть раз вернула «ничего не изменилось»,
дороже темы, которую за это время можно было выпустить.
