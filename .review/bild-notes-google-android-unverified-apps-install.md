## Процесс отбора
1. Прочитал policy-bild.md — таблица «чего здесь нет» не сработала (нет
   суицида/национальности/рекламы), приложения не открывал.
2. handoff-google-android-unverified-apps-install.md заполнен: image-hint —
   «экран смартфона Android с диалогом-предупреждением при установке;
   допустима нейтральная иллюстрация с логотипом Android/Google Play».
   NOTES_PATH не открывал — hint был непустой.
3. Тема без человека-субъекта (интерфейс + политика компании) — сразу B/A,
   а не поиск фото конкретного лица.
4. Прошёл по sources из frontmatter: два поста Android Developers Blog
   (03.2026 и 06.2026) и developer.android.com/developer-verification —
   всё официальные первоисточники Google, не в чёрном списке.
5. Через WebFetch собрал все изображения со страниц. Официальных
   ФОТОГРАФИЙ на этих страницах нет вообще — только векторные иллюстрации
   и одна content-инфографика с реальными датами (подтверждено отдельным
   WebFetch по developer.android.com/developer-verification: «No real
   smartphone photos are present on this page», только SVG/PNG-графика).
6. Проверил три кандидата на кадр 16:9 (bild-charts.md — кандидат
   похож на скриншот/инфографику, поэтому playbook открывал):
   - `260317_ADV Blog_Header.png` (4210×1254, декоративная flat-иллюстрация
     Android-робота со щитом) — при прогоне через prepare-image.py ушёл
     в `contain` с подложкой (обрезка потребовала бы 47% по ширине,
     выше MAX_CROP=0.45) → красный флаг по bild-charts.md, не тот кадр,
     отклонён.
   - `slide v3 (2).png` — «Sideloading is here to stay» (1920×800), реальный
     скриншот системного диалога «Don't install / Install anyway».
     Прогнал через prepare-image.py: cover, обрезка 26% по ширине,
     офсет [493,0]. Проверил результат глазами — обрезка отсекает левый
     край карточки диалога, кнопки упираются в край кадра без бордера,
     композиция выглядит сломанной. Не самодостаточный кусок → отклонён.
   - `ABL_83_Blog in line asset - ADV July.png` — «Timeline» (960×540,
     ratio точно 16:9): официальная инфографика Google с реальными датами
     (июнь/июль/август/30 сентября 2026, расширение на весь мир с 2027) —
     то есть ровно те факты, что и в статье. При прогоне через
     prepare-image.py: cover, обрезка 0%, апскейл 1.67× (в пределах
     MAX_UPSCALE=2.5 по актуальному коду скрипта). Весь контент виден,
     ничего не срезано, текст читаем на выходном размере — выбран.
7. `node scripts/photo-dupes.mjs --check` на исходнике до обработки —
   «свободен, за 2 дн. этот кадр не выходил».
8. Тематическая фототека (`stock-photos.json`) не подошла бы: темы cbu/sum/
   inflation/banking — не про Android, шаг B0 неприменим.
